## Scope and reproducibility

parse/schema contracts `0.1`. No Rust, Cargo, CLI or existing test code changed.
The harness imports only Node built-ins and invokes the same CLI for both
profiles; no schema conversion is duplicated. It prints assertions/measurements,
not raw records. It exits nonzero on any failed semantic or parity check.

```bash

node --check tools/runtime-evaluation/evaluate.mjs
node tools/runtime-evaluation/evaluate.mjs target/release/parser-cli
```

## Cases and meaning

Inputs are synthetic [`review.txt`](../../fixtures/runtime/review.txt),
[`review.csv`](../../fixtures/runtime/review.csv) and the existing typed/blank-cell
[`sample.xlsx`](../../fixtures/xlsx/sample.xlsx). The text fixture is tested both
as stdin and as a TXT file.

- [`attendance-supported.json`](../../fixtures/runtime/attendance-supported.json)
  is a small QualEvents-shaped example requesting `party_size` and `attending`.
- [`inventory-supported.json`](../../fixtures/runtime/inventory-supported.json)
  requests `units` and `available` for an unrelated stock-check profile.

Both supply their own record names, fields and aliases. Only currently supported
integer/boolean capabilities are used. The same unchanged engine/interface
returns `42` and `true` under the appropriate caller field names; incomplete
second records retain missing-field warnings and review status. These are not
complete consumer profiles or business-validity checks. Names, text fields,
datetime execution and full #19 conformance remain unsupported/unverified.

The [harness](../../tools/runtime-evaluation/evaluate.mjs) checks:

- Eight profile/format combinations plus 10/100/500-row CSV probes. Every
  success matches direct CLI stdout/stderr byte-for-byte at the same paths,
  repeats deterministically and has semantic value assertions.
- Embedded documents equal independent `inspect` results. All detected,
  assigned and unassigned candidate references resolve exactly. Header/unused
  coverage accounts for every canonical block/byte, including Unicode,
  whitespace, empty cells and typed XLSX values.
- Nine failure cases: malformed schema JSON, unsupported schema version,
  `text`/`person_name`/`datetime` execution, invalid UTF-8/CSV/XLSX, and the
  existing 64-KiB text-line limit. Each retains exact direct-CLI error bytes
  and exit `1`; path-containing errors remain the known #2 privacy gap.
- Input/schema guards, stdout/stderr caps, missing executable, deadline and
  caller cancellation. Cancel/deadline probes keep stdin open, then verify
  child closure/reaping and empty result bytes. All private temporary
  directories are removed, including failure paths.

Cancellation while CPU-intensive parsing, forced-kill escalation, concurrent
requests, malformed executable output and version mismatch are **not** covered
by these probes; they remain explicit #18 gates. The process is not an input
sandbox, and these guards do not replace #17's engine resource work.

### Bounded WASM feasibility check

The user's library-style preference makes installation and deployment simplicity
part of the decision. Preserve the process evidence above, but do not infer the
best package merely from today's CLI availability. No second invocation adapter
was built. With the already installed target and the same Rust 1.96.0 toolchain:

```bash
cargo check --locked --target wasm32-unknown-unknown -p parser-core -p parser-schema -p parser-formats
```

This passed in 6.79 seconds, including the pinned CSV/calamine/ZIP dependencies.
It proves target compilation/type checking only, not a linked or executing WASM
module, exported JS API, package size, semantic parity, memory or cancellation.
No target, global tool or dependency was installed for this check.

Source inspection found public text/TXT/CSV byte paths in
[`parser-formats`](../../crates/parser-formats/src/lib.rs), but `read_xlsx` still
requires a path and performs filesystem operations. The pinned calamine 0.36.1
already has `open_workbook_from_rs` and an `Xlsx<RS>` reader for `Read + Seek`,
as verified in the downloaded dependency and its
[versioned source](https://github.com/tafia/calamine/blob/v0.36.1/src/lib.rs).
Therefore a byte reader is a missing engine API, not a demonstrated calamine
or WASM impossibility. Adding it is outside this evaluation. Shared schema
conversion remains CLI-private (#12); the manifests contain no JS exports or
WASM binding/package. A complete call cannot be claimed from compilation alone.

A WASM package could remove native binary selection, child processes and
per-call temporary files. It still needs shared schema/byte entry points,
module/glue packaging, byte and result copying measurements, and a tested
interruption strategy. These unmeasured costs must be compared with the measured
process path before selecting the one production backend. Browser support is
not a prerequisite. The follow-up gate and ownership are recorded in ADR 0006;
no new engine work or second adapter was started here.

## Decision limits

Only the packaged CLI process was prototyped; the WASM check was compilation
and source inspection only. No WASM/native binding/service, shared schema
compiler or production wrapper was implemented. The proposed library caller
boundary and open backend gate are in [ADR 0006](../decisions/0006-library-interface-runtime-evaluation.md).
No message queue or separately operated service is wanted for initial integration.
The #19 independence gate remains planned, despite useful narrow two-profile
evidence here. No publication or deployment readiness is claimed.
